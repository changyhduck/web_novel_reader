# 小說閱讀器

本專案是一個以網頁方式實作的小說閱讀器，可同時管理多部小說。每部小說包含章節與插圖，並以獨立目錄整理內容。

本專案定位為自己使用的個人小說書架：在本機方便啟動並完成完整測試後，將同一份網站檔案放到自己的私人 Web Server 使用。重點是閱讀舒適、進度保存、內容維護與部署簡單；不規劃帳號、雲端同步、留言或離線下載功能。

## 小說目錄結構

可部署的網站檔案皆存放於專案根目錄下的 `web/` 子目錄。將整個 `web/` 目錄複製到網站空間後，即可作為網站根目錄使用。所有小說皆存放於 `web/novel/`；`novel/` 下的每一個直接子目錄代表一本小說。

小說內最大的內容單位是「幕」，每一幕下分成數個「章」。每一幕使用獨立子目錄，各章使用 Markdown（`.md`）檔案，該幕的插圖集中存放於幕目錄下的 `images/`。

```text
web_novel_reader/
├── README.md
└── web/                         ← 可直接部署的網站目錄
    ├── index.html                ← 網站入口
    ├── novel-index.json          ← 小說、幕與章節索引
    └── novel/
        ├── 小說名稱X/
        │   ├── meta.json
        │   ├── cover.jpg
        │   ├── 001_第一幕_XXXX/
        │   │   ├── 001_第1章_XXXX.md
        │   │   ├── 002_第2章_XXXX.md
        │   │   └── images/
        │   │       ├── 001_插圖01.jpg
        │   │       └── 002_插圖01.jpg
        │   └── 002_第二幕_YYYY/
        │       ├── 001_第1章_YYYY.md
        │       ├── 002_第2章_YYYY.md
        │       └── images/
        │           └── 001_插圖01.jpg
        └── 小說名稱Y/
            └── （依相同方式建立幕、章與插圖）
```

`novel-index.json` 由索引產生工具根據 `novel/` 的內容與各小說的 `meta.json` 建立。它包含小說名稱、作者、封面、別名、幕與章節順序、章節檔案路徑、章節字數，以及每本小說的章節數與總字數。網站只讀取此索引來呈現首頁與目錄，不依賴網站主機提供目錄清單，因此整個 `web/` 目錄可直接部署至一般靜態網站空間。

以下索引範例代表只有一章的小說，字數僅供示意；實際數值由工具計算：

```json
{
  "schemaVersion": 1,
  "contentVersion": "<索引內容的 SHA-256>",
  "assets": [
    {
      "path": "novel/小說名稱X/cover.jpg",
      "version": "<封面檔案的 SHA-256>",
      "width": 800,
      "height": 1200
    },
    {
      "path": "novel/小說名稱X/001_第一幕_XXXX/images/001_插圖01.jpg",
      "version": "<插圖檔案的 SHA-256>",
      "width": 1200,
      "height": 800
    }
  ],
  "novels": [
    {
      "id": "novel-x",
      "title": "小說名稱X",
      "author": "作者名稱",
      "aliases": ["另一個書名"],
      "description": "小說簡介。",
      "cover": "novel/小說名稱X/cover.jpg",
      "chapterCount": 1,
      "wordCount": 3000,
      "acts": [
        {
          "title": "第一幕：XXXX",
          "chapters": [
            {
              "id": "001_第一幕_XXXX/001_第1章_XXXX.md",
              "title": "第1章：XXXX",
              "path": "novel/小說名稱X/001_第一幕_XXXX/001_第1章_XXXX.md",
              "version": "<章節檔案的 SHA-256>",
              "wordCount": 3000
            }
          ]
        }
      ]
    }
  ]
}
```

### 命名與排序

- 幕目錄與章節檔名前加上三位數排序序號，例如 `001`、`002`，作為閱讀器排列幕與章的依據。
- 章節檔名前的序號表示該章在幕內的順序；名稱中的章號可以跨幕接續，也可以在每幕重新編號，依小說原本編排決定。
- 目錄與檔名使用底線分隔。Windows 檔名不能包含半形冒號 `:`，閱讀介面仍可顯示「第一幕：XXXX」與「第1章：XXXX」。
- 插圖檔名以所屬章節的排序序號開頭，再加上插圖編號，例如 `001_插圖01.jpg`、`001_插圖02.jpg`。
- 幕使用「排序序號_幕標示_標題」格式；章可使用「排序序號_章標示_標題」或沒有額外標題的「排序序號_章標示」格式。排序序號至少三位，以數值排序，同一層不可重複；序號可不連續。
- 顯示名稱時移除排序序號與章節的 `.md` 副檔名，將幕或章標示後的第一個底線改為全形冒號，標題內其他底線保留。例如 `001_第1章_陌生的房間.md` 顯示為「第1章：陌生的房間」。
- 章節標題由閱讀器在內文上方統一顯示；Markdown 不重複放置章名，內文小節使用二級以上標題（`##` 起）。
- 所有 Markdown 與 JSON 使用 UTF-8。只有符合幕命名格式的子目錄會被當作幕，封面用的 `images/` 等資源目錄不會被誤列入目錄。

### 小說資料

每本小說的根目錄必須包含 `meta.json`，用於儲存不適合放入目錄名稱的資料。小說的正式名稱以小說目錄名稱為準；別名則可用於首頁搜尋。

```json
{
  "id": "novel-x",
  "author": "作者名稱",
  "aliases": ["另一個書名", "英文名稱"],
  "description": "這是一段關於……的故事。",
  "cover": "cover.jpg"
}
```

- `id`：必填、全站唯一的固定識別碼，使用小寫英文字母、數字與連字號。改書名或小說資料夾名稱時保持不變，以保留閱讀紀錄。
- `author`：選填作者名稱，省略或空字串時顯示「作者未提供」。
- `aliases`：選填書名別名字串陣列，預設為空陣列。
- `description`：選填小說簡介，預設為空字串；可使用 Markdown 的段落、粗體與連結語法，首頁顯示時同樣進行安全過濾。
- `cover`：選填、相對於小說根目錄的本地封面路徑，例如 `cover.jpg` 或 `images/cover.jpg`；省略或空字串時使用預設封面。

章節第一版以「相對於小說根目錄的章節路徑」作為識別碼，不包含小說資料夾名稱。幕或章改名、移動或重新編號後，舊章節紀錄可能失效；不自動猜測對應章節，而是提示讀者重新選章。

封面檔案放在小說根目錄或其子目錄中。首頁會使用封面、作者與簡介呈現小說資訊。

## Markdown 章節與閱讀方式

章節整理的完整規則與可直接交給 AI 的指令，請參閱 [小說 Markdown 整理規範](NOVEL_MARKDOWN_RULES.md)。該文件涵蓋命名、段落、對話、換行、插圖與交付檢查。

小說內容直接提供 Markdown 檔案，不需要事先轉換成 HTML。章節內文與圖片引用範例如下：

```markdown
這裡是小說內文。

![本章插圖](images/001_插圖01.jpg)
```

圖片路徑以章節檔案所在的目錄為基準，因此可透過 `images/檔名` 引用同一幕的插圖。

### 段落與換行

第一版使用標準 Markdown 段落規則：空白行分隔段落；段落內單次換行視為軟換行，呈現為空格，不強制斷行。需要同一段落內明確斷行時，在行尾加反斜線。工具與閱讀器使用一致的解析規則，不啟用「所有換行自動轉成斷行」選項。

```markdown
「你回來了。」

「嗯，我回來了。」

信上只有兩行字：\
明天，老地方見。
```

上例的兩句對話為不同段落，信件的兩行則在同一段落內斷行。連續多個空白行不代表多倍段距；段距由閱讀器樣式統一控制。內文小節標題使用 `##`，不以空白行或空格手工排版。

### 內容呈現

閱讀器將負責：

1. 依幕與章的排序序號呈現目錄，並載入選取的 Markdown 章節。
2. 使用 Markdown 解析功能，將章節內容轉成 HTML 顯示於網頁中。
3. 以章節檔案所在目錄解析圖片的相對路徑，載入對應插圖。
4. 過濾不安全的 HTML，避免小說內容中的程式碼被執行。

內容維護者只需管理 Markdown 章節檔與圖片。瀏覽器不會自動將 Markdown 排版成小說頁面，這項轉換需由閱讀器實作。

## 網頁介面

### 導覽列

網頁最上方提供固定的導覽列，包含 **Home** 等功能入口。Home 連回首頁；其他功能項目將隨閱讀器功能擴充。

### 首頁

首頁列出所有可閱讀的小說。每本小說以一個列表項目呈現，至少顯示：

- 小說名稱
- 章節數量
- 總字數

點選小說名稱後，網頁會進入該小說的閱讀器頁面。

首頁由 `novel-index.json` 提供資訊，因此不必在載入首頁時下載所有章節內容。提供依正式書名、別名與作者搜尋；沒有搜尋結果時顯示提示並可清除搜尋條件。

字數統一以 Markdown 解析後的內文計算：排除所有標題、圖片（含替代文字）、程式碼區塊與 HTML 標記；一般連結只計顯示文字。剩餘文字只計 Unicode 字母與數字，每個字元算一字，標點、符號及空白不計。中文字每字算一字，英文按字母計，例如 `Hello 世界！` 為 7 字。小說總字數為所有章節字數加總，不包含作者與簡介；首頁提供此計算方式的簡短說明。

### 閱讀器

閱讀器頁面最上方保留導覽列，方便讀者隨時返回首頁或使用其他功能。

導覽列下方採左右雙欄版面：

- **左欄：小說目錄**。顯示目前小說的幕與章，讀者可點選章節切換閱讀內容。
- **右欄：小說內容**。上方提供以齒輪圖示呈現的設定按鈕；下方顯示選取章節經 Markdown 轉換後的內文與插圖。

目錄可展開或收合各幕，並標示目前閱讀的章節。章節數量較多時，左欄可獨立捲動，閱讀內容不會被遮住。

### 閱讀設定

讀者按下右欄上方的齒輪設定按鈕後，開啟閱讀設定視窗。設定視窗可調整：

- **字型大小**：設定小說內文的顯示大小。
- **字型**：預設使用正黑體，並可切換為標楷體。

設定應立即套用至目前閱讀的小說內容。

設定保存在目前瀏覽器中，讀者下次開啟網站時仍會沿用。為了在不同裝置上盡量維持中文字型的可讀性，正黑體與標楷體都應設定適當的系統字型作為替代字型。

第一版預設字級 20px、行距 1.8、亮色主題；字級可調整為 16–32px，行距可調整為 1.4–2.4。提供「恢復預設」按鈕。正黑體優先使用 Microsoft JhengHei，最後以 sans-serif 替代；標楷體優先使用 DFKai-SB、BiauKai 或 KaiTi，最後以 serif 替代。設定視窗註明實際字型取決於裝置；第一版不隨網站附帶字型檔。

### 章節切換

右欄內容結尾提供章節切換按鈕：

- 有前一章時，顯示「上一章」按鈕。
- 有下一章時，顯示「下一章」按鈕。
- 位於第一章時不顯示「上一章」；位於最後一章時不顯示「下一章」。

按鈕會依小說完整順序切換至相鄰章節，包含跨幕切換。切換至其他章時，內容捲動位置回到新章開頭。

### 閱讀進度與顯示偏好

閱讀器以固定小說 `id` 個別記錄最後閱讀的章節、段落索引、段落內的相對位置與章節內容版本。讀者從首頁再次開啟同一本小說時，會回到上次的位置；尚未閱讀的小說由第一章開始，也提供「從頭閱讀」入口。

還原位置前先套用閱讀設定，圖片預留尺寸避免載入時推動文字；字級或視窗大小改變後，以段落位置重新定位。復原後若使用者已開始捲動，不再強制跳回。章節內容版本改變時回到該章開頭並提示內容已更新；紀錄中的章節不存在時，顯示小說目錄與「原章節已變更」提示，讓讀者選章。

保存時機與保護規則：

- 捲動停止 500 毫秒後保存；持續捲動時最多每 2 秒保存一次，避免只依賴關閉網頁事件。
- 切章、返回首頁前先保存目前章節；頁面轉入背景或離開時再嘗試保存。瀏覽器突然終止時仍可能遺失最後尚未寫入的少量進度。
- 只有章節載入成功且位置復原完成後才啟用保存；載入失敗、切換過程及自動定位中的位置不覆蓋有效紀錄。舊章節的延遲保存工作在切章時完成或取消，不得寫到新章節。
- 字級或版面改變時先保留段落位置，重排與定位完成後再保存；顯示設定本身則在變更後保存。
- 閱讀紀錄包含格式版本與更新時間；瀏覽器歷史項目另外保存各自位置，不能只依靠一本小說的最後進度還原上一頁。

閱讀進度與全站共用的閱讀設定保存在目前網站的瀏覽器儲存空間，第一版不提供跨裝置同步。清除網站資料後紀錄會消失；更換網域也不會自動移轉。儲存不可用或資料損毀時回到預設值，顯示一次無法保存的提示，仍允許正常閱讀。提供清除本小說進度的操作，與恢復顯示設定分開。

閱讀設定除字型與字型大小外，也應提供行距和亮色、深色、護眼米色三種閱讀主題。電腦版限制內文最大寬度，避免單行文字過長；圖片會依內容欄寬縮放。

### 手機版

在較窄的螢幕上，閱讀器以內容欄為主，小說目錄改為可由按鈕開啟與關閉的面板。讀者選擇章節後自動收起目錄，以保留足夠的閱讀空間。

### 章節網址與瀏覽器操作

使用 `index.html` 的網址片段保存小說與章節，例如 `index.html#novel=novel-x&chapter=...`，各參數需 URL 編碼，不要求網站主機設定路由轉寫。提供複製目前章節連結的操作。

直接開啟指定章節連結時，指定章節優先於保存的進度，從該章開頭閱讀。重新整理保留目前章節並還原該章已保存的位置；瀏覽器上一頁／下一頁還原對應歷史項目的章節與位置。點目錄或章末切章則從新章開頭開始。無效小說網址顯示返回首頁入口，無效章節網址顯示該小說目錄，不偷偷改讀其他章節。

### 鍵盤與可讀性

齒輪按鈕具備「閱讀設定」的輔助文字標籤。設定視窗與手機目錄具備明確的關閉按鈕，支援 Esc、鍵盤焦點循環，關閉後焦點回到原按鈕。章節連結與按鈕可用鍵盤操作，並顯示焦點位置。章節切換後將閱讀焦點移至新章標題。

按鈕觸控區域至少 44 × 44px；不同主題下文字與焦點標示皆保持清楚。文字放大至 200% 時仍可操作，固定導覽列不可遮擋標題與控制項；手機不產生整頁橫向捲動。

### 載入狀態與錯誤處理

讀取索引或章節時顯示載入狀態。若索引、章節或插圖找不到，閱讀器要顯示清楚的錯誤訊息與可採取的操作，例如返回首頁或選擇其他章節，而不顯示空白頁面。

- 無小說時首頁顯示「尚無小說」；小說無章節時顯示「尚無可閱讀章節」，不顯示切章按鈕。
- 索引或章節載入失敗時可重試；失敗不覆蓋原本有效的閱讀進度。
- 圖片失敗只在圖片位置提示，不阻止閱讀其他內文；封面失敗改用預設封面。
- 快速連續切章時，只呈現最後選取的章節，較早的載入結果不得覆蓋新內容。

## 索引產生與驗證

索引工具規劃放在專案根目錄的 `tools/`，在上傳前執行，不需部署到網站。產生的索引包含 `schemaVersion`、內容雜湊版本，以及章節與圖片的版本資訊；首頁封面路徑統一轉成相對於 `web/` 的路徑，圖片尺寸也由工具收集以便預留版面。索引由工具管理，不手動修改。

工具必須驗證：

- `meta.json` 存在且可解析、欄位型別正確、小說 `id` 合法且唯一。
- 幕與章命名符合規則、同層排序序號無重複、章節文字可用 UTF-8 解碼。格式錯誤的章節不得無聲略過。
- 所有本地章節、封面與插圖存在，路徑大小寫與實體檔案一致，解析後不超出所屬小說目錄。第一版圖片使用本地檔案，外部一般連結只允許安全的協定。
- 每本小說的章節數與總字數符合實際加總。空幕不列入閱讀目錄，空小說可列於首頁並顯示無章節狀態。

錯誤訊息須指出檔案與原因。遺漏必填資料、壞連結與重複序號等錯誤阻止產生新索引，保留上一次成功的索引；缺少選填資料、空幕或空小說則給予警告。全部驗證成功後才一次替換索引，避免留下半份檔案。

### 索引欄位契約（版本 1）

以下欄位在產生的索引中全部必填。選填的來源資料由工具補成明確預設值；閱讀器不自行猜測缺漏欄位。前方範例的雜湊字串為佔位說明，正式值必須是 64 位小寫十六進位 SHA-256。

| 所屬物件 | 欄位與型別 | 規則／預設值 |
|---|---|---|
| 根物件 | `schemaVersion`: 整數 | 第一版為 `1`，格式不相容時升版。 |
| 根物件 | `contentVersion`: 字串 | 索引排除本欄位後，按固定鍵順序序列化為 UTF-8 所得的雜湊；不含生成時間，同內容重建結果相同。 |
| 根物件 | `novels`: 陣列、`assets`: 陣列 | 無資料為 `[]`。小說按 ID 排序，資源按路徑排序。 |
| 小說 | `id`、`title`: 字串 | 分別來自固定 ID 與小說資料夾名稱，不得為空。 |
| 小說 | `author`、`description`、`cover`: 字串；`aliases`: 字串陣列 | 缺省分別補 `""`、`""`、`""`、`[]`；作者空值由畫面顯示「作者未提供」。 |
| 小說 | `chapterCount`、`wordCount`: 非負整數；`acts`: 陣列 | 統計由實際章節加總，無章節時為 `0`、`0`、`[]`。 |
| 幕 | `title`: 非空字串；`chapters`: 陣列 | 幕與章依數值序號排列，空幕不輸出。 |
| 章節 | `id`、`title`、`path`、`version`: 非空字串；`wordCount`: 非負整數 | ID 為小說內相對路徑；version 為 Markdown 原始檔案位元組的雜湊。 |
| 圖片資源 | `path`、`version`: 非空字串；`width`、`height`: 正整數 | 版本取自圖片檔案位元組，尺寸為瀏覽器顯示方向的固有像素尺寸；讀不到尺寸視為驗證錯誤。 |

索引內 `path` 及非空 `cover` 統一為相對於 `web/`、以 `/` 分隔且未 URL 編碼的路徑；發出請求時才逐段編碼。同一張圖片在 `assets` 只列一次，包含引用到的封面與內文插圖；非空 `cover` 與章節圖片必須能對應至資源項目。第一版圖片格式限定 JPEG、PNG、WebP、GIF，以確保尺寸檢查行為一致。

索引格式檢查納入自動測試，閱讀器啟動也做必要型別與版本檢查。缺少必填欄位或不支援的 `schemaVersion` 時，不繼續解析或修改閱讀紀錄，顯示「資料格式不相容，請重新整理或確認部署版本」。

## 內容管理

- **管理多部小說**：在 `web/novel/` 下為每一本小說建立獨立子目錄。
- **整理幕與章**：在小說目錄下為每一幕建立子目錄，再將各章的 Markdown 檔案放入對應幕中。
- **整理插圖**：將插圖放入對應幕的 `images/` 目錄，並在章節中以相對路徑引用。
- **更新索引**：新增、修改或刪除小說內容後，重新產生 `web/novel-index.json`，再將完整的 `web/` 目錄部署至網站。

## 預覽、部署與更新

### 新增小說工具

提供獨立的「新增小說」入口，輸入小說名稱後，在 `web/novel/` 建立對應目錄與 `meta.json`。工具自動產生 `novel-` 加 UUID 的固定 ID，檢查全站無重複，並將選填欄位填為空字串或空陣列；不產生虛構章節或假封面。

對已有小說目錄，只在缺少 `meta.json` 時協助初始化；已有檔案一律保留，包括格式錯誤的檔案，改以提示要求修正。工具檢查目錄名稱是否合法、最終路徑位於 `web/novel/` 內；重複執行不得改變既有 ID 或覆蓋小說內容。新增完成後提示放入幕與章，再執行索引更新。這項初始化操作獨立於一般驗證，驗證不會自動改寫來源資料。

### 執行環境

網站採純靜態架構，第一版不需要帳號、資料庫或網站後端。閱讀器所需的腳本、樣式與解析套件均隨 `web/` 部署，避免依賴外部 CDN。資源使用相對於網站入口的路徑，支援網站根目錄與 `/reader/` 等子路徑部署；網址中的中文與特殊字元須正確編碼。

本機以 HTTP 服務將 `web/` 作為網站根目錄預覽，不以雙擊 HTML 的方式驗收章節載入。實際預覽及索引產生命令在工具完成後補充。

在 Windows 10 上，可直接雙擊專案根目錄的 `start.bat`。它會從自己的位置執行同目錄的 `start.ps1`，因此可透過桌面捷徑或從任意工作目錄啟動；網站啟動完成後會以 Microsoft Edge 開啟 `http://127.0.0.1:4173/`。`start.bat` 必須與 `start.ps1` 保持在同一個專案目錄，不能單獨移走。

### 本機啟動規格

- 提供 Windows 一鍵啟動入口，使用者不必手動切換目錄或輸入多個命令。工具先檢查所需執行環境，再驗證內容及更新索引，最後啟動本機 HTTP 服務並開啟瀏覽器。
- 使用固定且可設定的本機位址與連接埠，預設僅監聽 `127.0.0.1`。連接埠被占用時顯示原因，不默默換埠，以免閱讀紀錄看似消失；可由使用者改設定。
- 驗證失敗時列出檔案與原因，不宣告啟動或測試成功。服務需有明確的停止方式，重複啟動不得產生多個無法辨識的背景服務。
- 另提供獨立的檢查／測試入口，方便部署前執行；測試失敗不產生可發布版本。
- 本機工具與測試資料放在 `web/` 以外。Web Server 只需提供靜態檔案，不必安裝本機工具的執行環境。

以上為待實作的工具行為，並非目前已有的一鍵啟動功能。

### 本機與私人 Web Server 的一致性

本機測試與伺服器使用相同的 HTML、CSS、JavaScript、小說及索引，不另外維護兩套閱讀器。測試完成後，將當次通過驗證的 `web/` 封存為部署副本；上傳此副本，不在上傳前重新修改內容或重建另一份索引。

Web Server 需能提供 HTML、JavaScript、CSS、JSON、Markdown 與圖片檔案，正確處理 UTF-8 與檔案類型，並以 `index.html` 為入口。無需資料庫、API 或路由轉寫。伺服器的私人存取方式沿用既有配置，不在閱讀器中增加登入系統。

閱讀紀錄依瀏覽器及網站來源保存；本機與 Web Server 即使使用同一瀏覽器，也各自保存進度與設定，不會隨 `web/` 上傳。固定本機網址可保留本機紀錄，伺服器網址的紀錄則從實際使用後開始累積。

### 部署前測試與部署後確認

本機測試必須涵蓋下方全部第一版驗收項目，並另外確認：

- 分別以網站根目錄及 `/reader/` 子路徑測試同一份檔案。
- 使用含中文、空白檔名的小說，檢查大小寫、章節網址、封面與插圖路徑。
- 模擬慢速載入、失敗與重試、快速切章及快取更新；正常與異常資料分開測試，不修改自己的正式小說作為失敗案例。
- 使用桌面瀏覽器與手機尺寸測試，並檢查重新啟動後的閱讀紀錄及設定。測試結果記錄通過／失敗與對應的部署版本。

只有檢查與測試全部通過後才準備部署副本。私人 Web Server 上仍需做一次簡短確認：首頁、任一章節與插圖、跨幕切章、重新整理、子路徑及更新後的版本皆正常，確認伺服器設定未造成與本機不同的結果。

測試工具輸出一份可閱讀的摘要及機器可讀的結果，放在 `web/` 以外的測試報告目錄。報告記錄候選版本的完整檔案雜湊清單、測試時間、瀏覽器及環境，分別列出「資料／單元檢查」「瀏覽器操作測試」「人工確認」的通過、失敗、未執行與不適用狀態。不適用需附理由；未執行不能當作通過。

一鍵啟動只代表可以本機預覽，不能標示全部驗收完成。自動測試完成後仍需記錄人工檢查結果，工具不得代填。必要項目全部通過、且部署副本檔案雜湊與受測版本一致時，才能標記為「可部署」；測試後有任何檔案改變則重新驗證受影響項目並更新報告。部署後確認獨立記錄，不冒充本機已完成的結果。

更新流程：

1. 修改 Markdown、`meta.json` 與圖片。
2. 執行索引工具並修正驗證錯誤。
3. 完成本機檢查與測試，封存通過測試的 `web/` 為部署副本，並保留伺服器上一個可用版本。
4. 從部署副本上傳網站資源、章節與圖片，最後才上傳索引。主機若支援整個版本一次切換，優先使用版本切換。
5. 驗證線上新章節與圖片可讀後，再清理不再使用的舊檔案。

索引請求必須重新驗證快取，章節與圖片請求附上內容版本以避免沿用舊快取。主機快取設定亦須配合；讀到新索引時，清除記憶體中對應的舊章節快取。逐檔上傳不保證所有內容同時更新，故不可先刪除仍被舊索引引用的檔案。

### 程式與樣式版本

JavaScript 與 CSS 使用含內容雜湊的檔名，由 `index.html` 引用；本地解析套件也納入相同版本規則。HTML 與索引須重新驗證快取，帶雜湊的程式與樣式可長期快取。部署工具先準備這些最終檔案，再測試及封存，不在測試後重新產生程式版本。

逐檔部署時，先上傳新程式、樣式、小說與圖片，再更新 `index.html`，最後更新索引。更新期間保留舊版程式檔案，若索引格式變更，優先使用整個部署版本切換。已開啟的舊閱讀器若讀到不支援的索引版本，提示重新整理且不清除進度；重新整理後仍不相容則提示檢查部署，不無限自動重整。

前端程式版本與索引內容版本分開管理：新增章節不必改程式版本，修改程式也不應讓未變更章節的閱讀位置失效。驗收覆蓋暖快取下更新程式／樣式、只更新小說，以及版本不相容三種情境。

## 第一版實作順序與驗收

以下皆為待實作規格，依序完成：

| 階段 | 交付內容 | 驗收重點 |
|---|---|---|
| 1. 內容與索引 | 資料驗證、名稱解析、字數統計、版本資訊 | 兩本小說、多幕與跨幕章號皆正確；錯誤資料不覆蓋有效索引。 |
| 2. 基本閱讀 | 首頁搜尋、目錄、Markdown 與插圖、跨幕切章 | 首末章按鈕正確；章名不重複；空資料及缺檔有可操作的提示。 |
| 3. 閱讀體驗 | 手機目錄、設定視窗、字型／字級／行距／主題 | 桌面與手機皆可閱讀；鍵盤及放大文字操作正常；設定即時生效並保存。 |
| 4. 進度與網址 | 閱讀位置、章節連結、歷史操作 | 重整、返回、改字級及圖片延遲載入不造成錯誤跳章；明確章節連結不被舊進度覆蓋。 |
| 5. 部署驗證 | 本機預覽與更新流程 | 根目錄及子路徑部署都可用；內容更新後讀到新版本；儲存不可用時仍能閱讀。 |

驗收另需覆蓋：重複小說 ID、幕／章排序衝突、路徑大小寫不符、惡意 HTML 與連結、快速切章、小說改名但 ID 不變、章節改名及內容更新後的進度復原。索引示例中的數字是示意值，正式索引須由實際內容計算。

帳號、雲端同步、留言與離線下載不在本專案開發範圍內。進度匯入匯出目前也不列入第一版；如日後確有手動搬移紀錄需求，再另行評估。
